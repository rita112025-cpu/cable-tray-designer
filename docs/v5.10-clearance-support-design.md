## 1. 目標
在不動既有驗證合約與 transaction 架構前提下，擴展電纜橋架資料模型，納入：
- 豎向淨空保留區
- 支架規格與空間佔用（第一階段為屬性，第二階段獨立元件化）
- 區分「實體碰撞」與「淨空侵入」，避免過度告警

---

## 2. 欄位定義

### 2.1 Tray 本體與淨空
| 欄位 | 語意 | 單位 | 未知/空白時行為 |
|---|---|---|---|
| `elevation` | 托盤底面高程 | mm | 沿用現有邏輯；畫面顯示：`FFL = Tray 底面高程 (mm)` |
| `trayHeight` | 托盤本體豎向高度 | mm | 空白=未知；退回 2D 平面碰撞規則 |
| `clearanceAbove` | 托盤上方保留淨空 | mm | 空白=不要求上方淨空 |
| `clearanceBelow` | 托盤下方保留淨空 | mm | 空白=不要求下方淨空 |

### 2.2 支架 — 第一階段（Tray 屬性）
| 欄位 | 語意 | 單位 | 備註 |
|---|---|---|---|
| `supportType` | 支架型式 | 字串 | 例：`channel` / `hanger` / `bracket` / `trapeze` |
| `supportSpacing` | 預設安裝間距 | mm | 空白=未指定 |
| `supportOverhang` | 支架相對 Tray 輪廓向外延伸的單側距離（水平方向） | mm | 用於未來的 XY 干涉檢查；刻意不叫 `depth`，避免被誤解成垂直深度 |
| `supportDrop` | 結構面至托盤底面的落差（吊桿長度 / 安裝落差） | mm | **不是支架實體的高度**；空白=未知。支架獨立元件化後，實體高度另用 `Support.height` 表達 |

### 2.3 支架 — 第二階段（獨立元件，後續迭代）
```
Support {
  id           // 唯一編號
  trayId       // 所屬 Tray
  x, y         // 安裝座標
  zBottom, zTop // 支架自身 Z 範圍
  type         // 對應 supportType
  width, overhang, height // 實體輪廓（overhang = 相對 Tray 輪廓的水平外伸；height = 支架實體高度，與 supportDrop 不同）
}
```
> 第一階段僅記規格；不預估位置、不產生虛擬支架實體。

## 3. Z 區間語意

```
本體實體區間：
  [zPhysicalMin, zPhysicalMax]
  = [elevation, elevation + trayHeight]

擴展淨空保留區間：
  [zReservedMin, zReservedMax]
  = [
      elevation - clearanceBelow,
      elevation + trayHeight + clearanceAbove
    ]

任一 clearance 空白時，該側不向外擴展，
僅以本體區間做為判定邊界。
```

## 4. 碰撞判定模型

### 4.1 三層判定規則

| 碰撞類型 | 判定條件 | 結果 |
|---|---|---|
| **實體 ↔ 實體** | XY 重疊 **AND** zPhysical 區間重疊 > 1mm | ❌ Collision — 阻擋提案、顯示紅框 |
| **實體 ↔ 淨空區** | XY 重疊 **AND**（`A.physical ∩ B.reservedOnly > 1 mm` **或** `B.physical ∩ A.reservedOnly > 1 mm`），且**該對元件不構成實體↔實體碰撞** | ⚠️ Clearance Warning — 提示、不阻擋 |
| **淨空區 ↔ 淨空區** | 僅 reserved 區間重疊、雙方本體未接觸 | ✅ 不判定、不警告 |

其中 `reservedOnly = reserved − physical`（保留區扣掉本體區間，即上方與下方各一段淨空帶，`Z` 為兩段區間）。
用 `reservedOnly` 而不是整個 `reserved`，並且「已判為實體碰撞的元件對不再重複產生 Clearance Warning」，
避免同一對元件同時被算成 Collision 與 Clearance Warning。

### 4.2 未知處理原則
- `trayHeight` 空白 → 退回 v5.6 規則：僅同 elevation 才比較、不擴展 Z
- `clearanceAbove/Below` 任一空白 → 該側不擴展、邊界退至本體輪廓
- 任一端欄位不足 → 不升級判定等級、不虛假安全

### 4.3 連接處高度驗證（沿用 v5.9）
- 兩側 `trayHeight` 皆有值且不同 → ⚠️ Tray Height 不一致
- 任一空白 → 跳過本項檢查

## 6. 已知限制
- Reducer 僅單一 `trayHeight`；兩端高度不同的轉接尚無法精確表達，僅提示警告
- 淨空區重疊不告警，避免大量濫報；專案嚴格要求時可手動升級為阻擋
- 支架空間佔用第一階段不做自動位置推算；不填入虛擬實體
